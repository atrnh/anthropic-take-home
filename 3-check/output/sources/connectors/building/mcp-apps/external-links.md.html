1 > ## Documentation Index2 > Fetch the complete documentation index at: https://claude.com/docs/llms.txt3 > Use this file to discover all available pages before exploring further.4 5 # Opening external links from MCP Apps6 7 > How Claude handles ui/open-link requests, and how directory connectors can allowlist destinations to skip the confirmation modal8 9 When your MCP App sends a `ui/open-link` request, Claude shows an "Open external link" confirmation modal before navigating. This protects users from being silently redirected by an embedded app.10 11 Directory connectors can declare a set of trusted destinations that open immediately without the modal. Custom connectors and locally configured servers always show the modal.12 13 ## Default behavior14 15 A `ui/open-link` request displays a confirmation modal showing the destination URL. The link opens in a new tab when the user confirms; the request resolves as cancelled if they dismiss the modal.16 17 ## Allowlisting link destinations18 19 If your connector is published in the [Connectors Directory](/docs/connectors/directory), you can declare destinations that skip the modal. Provide them in the **Allowed link URIs** field when you [submit](/docs/connectors/building/submission) or update your directory listing.20 21 Each entry must be one of two shapes:22 23 | Entry shape       | Example                         | Matches                                                                                                                                                               |24 | ----------------- | ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |25 | HTTPS origin      | `https://docs.example.com`      | Any `https://` URL whose hostname is exactly `docs.example.com` (case-insensitive). Subdomains do not match implicitly; list each one you need. Port is not compared. |26 | Custom URI scheme | `example-app` or `example-app:` | Any URL with the scheme `example-app:`, typically a deep link into your native mobile or desktop app.                                                                 |27 28 Entries that do not fit one of these shapes are ignored. This includes bare hostnames such as `example.com`, `http://` origins, and malformed values.29 30 ### Example31 32 Given the following allowlist:33 34 ```text theme={null}35 https://example.com36 https://docs.example.com37 example-app38 ```39 40 These destinations open immediately:41 42 * `https://example.com/pricing`43 * `https://docs.example.com/getting-started?ref=claude`44 * `example-app://open/project/123`45 46 These destinations still show the confirmation modal:47 48 * `https://blog.example.com` (subdomain not listed)49 * `http://example.com` (not HTTPS)50 * `https://example.com.attacker.net` (different hostname)51 52 ### Restrictions on custom schemes53 54 A custom-scheme entry must name a scheme your application registers and owns. Entries that name a generic, browser-internal, or platform-reserved scheme are rejected. This includes `http`, `https`, `file`, `data`, `javascript`, `blob`, `mailto`, `tel`, `sms`, `intent`, `android-app`, browser-extension schemes, and Windows shell schemes such as `search-ms` and `shell`.55 56 ## User-activation requirement57 58 The modal is bypassed only when the `ui/open-link` request follows a real user gesture in your app, such as a button click.59 60 If your app sends `ui/open-link` without a preceding gesture (programmatically, on a timer, or after the browser's activation window has expired), the modal is shown so the user's confirmation click supplies the gesture the browser requires to open a new tab.61 62 <Note>63   A bypassed `ui/open-link` request resolves successfully once the open is attempted; it does not indicate whether the browser actually opened the tab. Do not treat the response as confirmation that the user reached the destination.64 </Note>65 66 ## Design for the modal67 68 Even with an allowlist configured, your app should remain usable when the modal appears:69 70 * Custom and local connectors always show the modal. Your app may run outside the directory during development or in self-hosted deployments.71 * Destinations not on your allowlist, or added since your last published directory update, show the modal.72 * Requests without user activation show the modal.73 74 Provide enough context in your UI that the destination URL shown in the modal is recognizable to the user.
