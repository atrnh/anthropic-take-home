1 > ## Documentation Index2 > Fetch the complete documentation index at: https://claude.com/docs/llms.txt3 > Use this file to discover all available pages before exploring further.4 5 # Blend your MCP App with Claude's theme6 7 > Make your widget background transparent and style it with Claude's style variables8 9 Claude renders MCP Apps inside a sandboxed iframe, and every frame between your widget and the chat surface already has a transparent background, so the conversation can show through. When you leave your own background transparent and style text and borders with the host's [style variables](/docs/connectors/building/mcp-apps/design-guidelines#style-variables), your app looks like part of the conversation rather than an embedded box, and it follows the user's light or dark mode automatically.10 11 The snippets on this page assume you have registered a UI resource and created an `App` instance from `@modelcontextprotocol/ext-apps`. See the [SDK Quickstart](https://modelcontextprotocol.github.io/ext-apps/api/documents/Quickstart.html) if you haven't.12 13 ## Let the host background show through14 15 Three settings on your side keep the transparency intact.16 17 ### Don't paint a body background18 19 Any opaque background on `<html>` or `<body>` hides the chat surface behind it. Explicitly set both to `transparent`:20 21 ```css theme={null}22 html,23 body {24   margin: 0;25   background: transparent;26 }27 ```28 29 ### Declare `color-scheme` in your document head30 31 Browsers give iframe documents an opaque canvas backdrop (white in light mode, near-black in dark mode) when the iframe's [`color-scheme`](https://developer.mozilla.org/docs/Web/CSS/color-scheme) differs from the embedding page. Declaring both schemes opts your document into whichever mode the host is in, so the browser drops the backdrop and makes the CSS [`light-dark()`](https://developer.mozilla.org/docs/Web/CSS/color_value/light-dark) values in Claude's tokens resolve correctly:32 33 ```html theme={null}34 <meta name="color-scheme" content="light dark" />35 ```36 37 ### Request a borderless frame38 39 Set [`prefersBorder: false`](https://modelcontextprotocol.github.io/ext-apps/api/interfaces/app.McpUiResourceMeta.html#prefersborder) in your UI resource's [`_meta.ui`](https://modelcontextprotocol.github.io/ext-apps/api/interfaces/app.McpUiResourceMeta.html) object so the host doesn't wrap your widget in its own bordered card. Claude web's default is already borderless, but other hosts differ, so being explicit keeps your app portable. Register the resource with [`registerAppResource`](https://modelcontextprotocol.github.io/ext-apps/api/functions/server-helpers.registerAppResource.html):40 41 ```ts theme={null}42 import {43   registerAppResource,44   RESOURCE_MIME_TYPE,45 } from "@modelcontextprotocol/ext-apps/server";46 47 registerAppResource(server, "My Widget", "ui://my-app/widget.html", {}, async () => ({48   contents: [49     {50       uri: "ui://my-app/widget.html",51       mimeType: RESOURCE_MIME_TYPE,52       text: widgetHtml, // the bundled HTML string of your widget; see the SDK Quickstart53       _meta: {54         ui: {55           prefersBorder: false,56           // lets applyHostFonts load Anthropic Sans; see "Allow the host font origin in your CSP"57           csp: { resourceDomains: ["https://assets.claude.ai"] },58         },59       },60     },61   ],62 }));63 ```64 65 ## Apply the host's style variables66 67 Claude passes a [`hostContext`](https://modelcontextprotocol.github.io/ext-apps/api/interfaces/app.McpUiHostContext.html) object to your widget during the [`connect()`](https://modelcontextprotocol.github.io/ext-apps/api/classes/app.App.html#connect) handshake. The fields relevant to theming are:68 69 | Field              | Contents                                                                                                                                                   |70 | :----------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------- |71 | `theme`            | `"light"` or `"dark"`                                                                                                                                      |72 | `styles.variables` | CSS custom properties: `--color-background-*`, `--color-text-*`, `--color-border-*`, `--color-ring-*`, `--font-*`, `--border-radius-*`, `--border-width-*` |73 | `styles.css.fonts` | `@font-face` rules for Anthropic Sans, served from `https://assets.claude.ai`                                                                              |74 75 The [Style variables](/docs/connectors/building/mcp-apps/design-guidelines#style-variables) section of the design guidelines lists every variable and its light- and dark-mode value.76 77 ### Read `hostContext` and listen for changes78 79 The [`App`](https://modelcontextprotocol.github.io/ext-apps/api/classes/app.App.html) class exposes the initial context via [`getHostContext()`](https://modelcontextprotocol.github.io/ext-apps/api/classes/app.App.html#gethostcontext) once `connect()` resolves, and delivers subsequent updates (such as the user toggling dark mode) through the [`hostcontextchanged`](https://modelcontextprotocol.github.io/ext-apps/api/types/app.AppEventMap.html) event. Register the listener before you connect so you don't miss an early update.80 81 The SDK provides three helpers that do the DOM work for you, plus React hooks that wrap them:82 83 * [`applyDocumentTheme(theme)`](https://modelcontextprotocol.github.io/ext-apps/api/functions/app.applyDocumentTheme.html) sets `<html data-theme>` and the root `color-scheme`, so `[data-theme="dark"]` selectors and `light-dark()` values resolve correctly.84 * [`applyHostStyleVariables(variables)`](https://modelcontextprotocol.github.io/ext-apps/api/functions/app.applyHostStyleVariables.html) writes every entry in `styles.variables` onto `:root` as a CSS custom property.85 * [`applyHostFonts(fontCss)`](https://modelcontextprotocol.github.io/ext-apps/api/functions/app.applyHostFonts.html) injects the host's `@font-face` rules once.86 * [`useApp(options)`](https://modelcontextprotocol.github.io/ext-apps/api/functions/_modelcontextprotocol_ext-apps_react.useApp.html) creates and connects the `App` instance for you in React.87 * [`useHostStyles(app, hostContext)`](https://modelcontextprotocol.github.io/ext-apps/api/functions/_modelcontextprotocol_ext-apps_react.useHostStyles.html) applies all of the above and re-applies on `hostcontextchanged`.88 89 Keep the `<meta name="color-scheme">` tag from the previous section even though `applyDocumentTheme` also sets `color-scheme` at runtime. The tag covers the first paint before your script runs and prevents an opaque-backdrop flash.90 91 <CodeGroup>92   ```ts TypeScript theme={null}93   import {94     App,95     applyDocumentTheme,96     applyHostFonts,97     applyHostStyleVariables,98     type McpUiHostContext,99   } from "@modelcontextprotocol/ext-apps";100 101   function applyHostContext(ctx: Partial<McpUiHostContext>) {102     if (ctx.theme) applyDocumentTheme(ctx.theme);103     if (ctx.styles?.variables) applyHostStyleVariables(ctx.styles.variables);104     if (ctx.styles?.css?.fonts) applyHostFonts(ctx.styles.css.fonts);105   }106 107   const app = new App({ name: "my-app", version: "1.0.0" });108 109   // Updates carry only the fields that changed.110   app.addEventListener("hostcontextchanged", (changed) => applyHostContext(changed));111 112   await app.connect();113   const initial = app.getHostContext();114   if (initial) applyHostContext(initial);115   ```116 117   ```tsx React theme={null}118   import { useApp, useHostStyles } from "@modelcontextprotocol/ext-apps/react";119 120   function Widget() {121     const { app } = useApp({122       appInfo: { name: "my-app", version: "1.0.0" },123       capabilities: {},124     });125     // Applies theme + CSS variables + fonts, and re-applies on host-context-changed.126     useHostStyles(app, app?.getHostContext());127     return <div className="card">…</div>;128   }129   ```130 </CodeGroup>131 132 ### Reference the variables in your CSS133 134 Once the variables are on `:root`, reference them directly. Provide fallbacks so the widget is still readable when rendered outside a host:135 136 ```css theme={null}137 body {138   font-family: var(--font-sans, system-ui, sans-serif);139   color: var(--color-text-primary, light-dark(#141413, #faf9f5));140 }141 .card {142   border: var(--border-width-regular, 0.5px) solid var(--color-border-primary);143   border-radius: var(--border-radius-md, 8px);144 }145 ```146 147 <Note>148   Claude's token values use CSS `light-dark()`, so once `applyDocumentTheme` has set the root `color-scheme`, every `--color-*` variable resolves to the right variant without any `[data-theme]` selectors on your side.149 </Note>150 151 ### Allow the host font origin in your CSP152 153 For `applyHostFonts` to load the `@font-face` files, your resource's [`_meta.ui.csp`](https://modelcontextprotocol.github.io/ext-apps/api/interfaces/app.McpUiResourceMeta.html#csp) allowlist must include `https://assets.claude.ai` in [`resourceDomains`](https://modelcontextprotocol.github.io/ext-apps/api/interfaces/app.McpUiResourceCsp.html#resourcedomains) (shown in the [`registerAppResource` snippet above](#request-a-borderless-frame)). `resourceDomains` also adds the listed origins to `script-src` and `style-src`, so keep it to origins you trust to serve executable code; prefer bundling third-party fonts into your widget rather than allowlisting public CDNs.154 155 ## Related topics156 157 * [Design guidelines: Style variables](/docs/connectors/building/mcp-apps/design-guidelines#style-variables) and [Visual design](/docs/connectors/building/mcp-apps/design-guidelines#visual-design) for the full variable palette and usage guidance.158 * [SDK API reference](https://modelcontextprotocol.github.io/ext-apps/api/index.html) for `App`, `McpUiHostContext`, and `McpUiResourceMeta`.
