Some are verified by Anthropic and others are community connectors; see [connector verification](/docs/connectors/verification).23 24 ## Adding custom connectors25 26 You can manually add any third-party connector to Claude as long as you have the URL of that remote MCP server.27 28 <Warning>29   **Security Notice**: Custom connectors allow connections to unverified services. Claude can access and perform actions within these services, so review security considerations carefully.30 </Warning>31 32 ### For Team and Enterprise plans33 34 **Owners must:**35 36 1. If your dialog shows a name, URL, and Advanced settings on one screen, your organization has the earlier version; the steps above still apply.68 </Note>69 70 **Name**: the display name shown in the connectors list.71 72 **MCP server URL**: the HTTPS address where the server accepts MCP requests, for example `https://mcp.example.com/mcp`. After you continue, Claude checks the URL and pre-fills the authentication settings it detects, marked "Detected."73 74 **Authentication**: how people connect to the server.75 76 * **Sign in now**: each user signs in through the server's OAuth flow before using it.77 * **Sign in when needed**: Claude connects without credentials and prompts users to sign in when the server asks.78 * **No sign-in**: anyone with access to the server URL can use the connector. If the server uses an API key, choose **No sign-in** and add the key under **Request headers**; Claude stores it as the connector's credential.79 80 **OAuth client** (shown unless you chose **No sign-in**): how Claude identifies itself to the server's authorization server.81 82 * **Use Claude's published identity** (recommended): the server reads Claude's client details from a URL Anthropic hosts (Client ID Metadata Document). Nothing to set up; the server must support it.83 * **Register automatically**: Claude registers OAuth clients with the server as users connect (Dynamic Client Registration). Works with most servers, but adds client registrations over time.84 * **Use your own OAuth client**: enter a client ID you registered with the server. Leave the secret blank unless your authorization server requires one. See [Authentication for connectors](/docs/connectors/building/authentication).85 86 **Request headers**: fixed credentials such as API keys, sent on every request. See [Authenticating with request headers](#authenticating-with-request-headers).87 88 **Advanced > Transport**: set from the URL automatically; a URL ending in `/sse` selects the older SSE transport. Change it only if the server's documentation says to.89 90 ## Authenticating with request headers91 92 <Note>93   Request header authentication is in beta and available to a limited set of organizations. If you don't see the **Request headers** section in the Add custom connector dialog, your organization doesn't have access yet.94 </Note>95 96 If your MCP server authenticates with an API key, bearer token, or other fixed credential instead of OAuth, you can configure it in the **Request headers** section of the Add custom connector dialog. Claude stores each header value securely, does not show it again after you save, and sends it on every request to your server.97 98 Request headers suit services where everyone in your organization shares one credential, such as an internal tool or a service account. If each person needs to sign in with their own account, use OAuth instead.99 100 You can also use request headers in addition to OAuth, including OAuth with your own pre-registered client credentials. Headers configured on an OAuth connection are sent on every request alongside the OAuth bearer token. This is useful for verifying where a request came from, passing additional client metadata, or working with tunnels and gateways that need their own routing header. The one exception is `Authorization`: OAuth owns that header, so it cannot be configured as a request header on an OAuth connection.101 102 ### Adding a request header103 104 1. In the Add custom connector dialog, open **Request headers**.105 2. Select a header name from the list, or choose **Custom header** to enter a different name. The list offers standard authentication and routing header names such as `authorization`, `x-api-key`, and `x-auth-token`, which every connector can use. Anthropic reviews and approves each custom header name before Claude will send it to a third-party server, which prevents connector configuration from being used to send arbitrary header names. If you enter a header name that isn't approved, Claude rejects the save with an error. To request approval for a custom header name, contact [Claude support](https://support.claude.com/en/articles/9015913-how-to-get-support).106 3. Enter the header value exactly as your server expects to receive it.107 4. Choose whether the header is **Required**. When a required header has no stored value at connection time, the connection fails. When an optional header has no value, Claude simply omits it from the request.108 5. Repeat for any additional headers your server needs (you can add up to four), then click **Add**.109 110 ### Enter the full header value111 112 Claude sends the value exactly as you enter it. It does not add an authentication scheme or any other prefix.113 114 For an `Authorization` header, include the scheme in the value:115 116 | You enter           | Claude sends                       |117 | ------------------- | ---------------------------------- |118 | `Bearer your-token` | `Authorization: Bearer your-token` |119 | `your-token`        | `Authorization: your-token`        |120 121 Most servers that use bearer tokens reject the second form. If your server's documentation shows `Authorization: Bearer YOUR_TOKEN`, enter `Bearer ` followed by your token, including the space. The same applies to Basic authentication: enter `Basic ` followed by the base64-encoded credentials.122 123 ## Managing connectors124 125 To edit a connector's name or URL, or to remove a connector:126 127 1. Go to **Customize > Connectors** (Team and Enterprise owners: **Admin settings > Connectors**)128 2. Click "Remove" or select the three-dot menu129 3.
