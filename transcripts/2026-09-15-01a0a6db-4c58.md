## Proposed plan

### 1. Define what deserves a flag

Use the [audit memo](~/.codex/worktrees/1cf6/anthropic-take-home/docs/1-audit/audit-memo.md) and [disposition ledger](~/.codex/worktrees/1cf6/anthropic-take-home/docs/1-audit/disposition-ledger.md) to assemble a small labeled set:

- **Problematic repetition:** shared plugin definitions, repeated MCPB explanations, and overlapping listing-management guidance.
- **Acceptable repetition:** short orientation text, necessary warnings, and repeated steps that make each context-specific procedure complete.
- **Related but distinct content:** general authentication versus lazy authentication, or a reference page versus instructions that use it.

Each example needs an editorial verdict and a short reason. These are candidate examples to inspect, not assumed detector successes.

### 2. Build one small, deterministic checker

Add a Python command under `docslint/` that reads the **existing 54-page snapshot** and its manifest.

It would compare substantial prose passages using normalized word sequences, excluding code, navigation, and short boilerplate. Start with exact and near-exact overlap; tune the minimum passage length and similarity threshold against part of the labeled set.

Each finding should show:

- Both source paths and line numbers.
- The matching excerpts and similarity score.
- A suggestion to review whether the explanation should have one maintained source.

Keep findings advisory. Similar wording alone cannot establish that content should be merged.

### 3. Run it and review the mistakes

Run against all 54 pages and commit a readable results report. Review every finding if the volume is manageable, and check a separate set of known examples that we did not use for tuning.

Report raw counts alongside:

- **Precision:** what fraction of flags identify actionable duplication?
- **Misses:** which labeled duplication examples did it fail to catch?
- Actual false positives and false negatives, with explanations.

The [task #3 requirements](~/.codex/worktrees/1cf6/anthropic-take-home/docs/roadmap.md) explicitly ask for cases the check got wrong. We should preserve those in the report, including paraphrased duplication that a lexical checker misses.

### 4. Set an operating policy

I’d propose an initial target of **at least 90% actionable findings**, meaning at most one unhelpful flag in ten, for advisory use. This is a proposed acceptance threshold, not a measured result. Reviewer attention is the scarce resource, so we should favor precision and make the coverage limits explicit.

Document how to keep it useful:

- Rerun the labeled examples whenever the checker changes.
- Review new findings when the corpus changes.
- Investigate falling precision, missed known examples, or sudden changes in passage counts.
- Record accepted exceptions with a reason and revisit them when the source changes.

### 5. Package the submission

Produce:

- One runnable checker and a small runnable verification file.
- A labeled evaluation set.
- A results report with real mistakes and limitations.
- A README covering the command, evaluation, maintenance, and GitHub location.

**First checkpoint:** inspect the candidate passages and confirm that text overlap catches enough meaningful duplication to justify this approach. Then build the smallest version that demonstrates it. No new scrape is needed to meet the assignment, and the pinned corpus makes the results reproducible.
